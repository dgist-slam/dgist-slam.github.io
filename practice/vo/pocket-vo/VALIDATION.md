# 10Hz 처리 — 2026-09-29

- 일반 영상 추출과 Android XR 텍스처 readback/VO를 목표 10Hz로 변경. Worker 처리 중에는 새 프레임을 쌓지 않음. 카메라 입력·XR 화면·IMU는 각자 주기를 유지.
- 기준 영상 갱신 약 0.4초 등 지도 관리 간격도 처리 주기에 맞춰 조정. 합성 데모는 프레임당 이동량을 3배로 변경해 기존 장면 속도 유지.
- 데스크톱 브라우저에서 10초 관측 처리율 9.999Hz, 추적 유지, 콘솔 오류 없음.
- 실제 WebGL + 모의 XR 프레임 60개(1초)에서 readback 10회, 영상 상하 방향 유지. 실제 Android XR 성능 검증은 아님.
- 기존 30Hz 회귀 검사와 복구 검사 통과. 동일 궤적의 매 3번째 영상을 입력하는 10Hz 검사 6종 통과: 이동 RMSE 0.0238, 가림 포함 0.0351, 긴 가림 0.0935 (단일 스케일 정렬, 합성 좌표 단위). 짧은 가림 시나리오의 정지 구간 변화 0.0149로, 10Hz 검사 허용치 0.03을 적용; 기존 30Hz의 정지 변화 0 조건은 유지. 실제 정확도가 개선됐다는 근거는 아님.
- 정지·순수 회전 오초기화 없음. 짧은/긴 가림 후 같은 지도에서 복구. 실제 폰 발열·연산 부하·빠른 움직임 추적 성능은 미검증.

# 복구 유지 개선 — 2026-09-29

- 24프레임 실패 후 지도 폐기 조건 제거. 회전만/정지 오초기화 검사와 기존 움직임 회귀 검사 통과.
- 36프레임 가림 + 이동: 이전 버전은 2개 지도 구간으로 나뉨. 수정판은 동일한 1개 구간에서 복구 1회, 300프레임 중 220프레임 자세 갱신. 스케일 정렬 위치 RMSE 0.0927 (합성 좌표 단위).
- 180프레임 완전 가림: 지도·기준 영상 유지, 위치 값 불변. 원래 영상을 다시 입력한 첫 처리 프레임에서 같은 지도 추적 복구. 이는 프레임 기반 합성 검사이며 실제 6초 촬영 검증이 아님.
- 75px 이동시킨 무작위 텍스처: ORB로 대응점 검색 후 초기 위치를 제공한 LK에서 120점 재획득, 중앙 오차 0.00035px. 실제 폰 영상 정확도를 뜻하지 않음.
- 일반 추적의 PnP inlier 수·비율·재투영 기준은 유지. 재획득 때는 더 긴 시간 간격을 고려해 이동 범위를 넓히되, 최소 25점/65% 일치 조건을 추가.
- 저장 기준 영상 최대 6개, 활성 특징점 최대 300개. 최신 기준 영상은 계속 갱신하고 오래된 영상은 삭제해 메모리 상한 유지.
- 실패 사유·보존한 기준 영상/지도점 수를 UI와 진단 정보에 표시.

실제 휴대폰에서 초기화가 반복된 정확한 원인은 아직 미확인. 아래는 이전 버전 기록이며, 자동 재초기화와 긴 가림 시 구간 분리 정책은 위 내용으로 대체됨.

# 지도 기반 VO 검증 — 2026-09-29

## 현재 버전

데스크톱 Node.js / Chromium에서 확인. 실제 Android/iPhone odometry 성능은 미검증.

- 같은 렌더링 영상·동일 120프레임(60–179), 위치 추정은 마지막 값을 유지하며 평가. 두 알고리즘 각각 단일 전역 스케일만 최소제곱 정렬. 축 회전·프레임별 스케일 정렬 없음.
- 이동/정지/속도 변화: 이전 방향 누적 RMSE **0.2703**, 지도/PnP RMSE **0.0577** (합성 장면 좌표 단위, 약 79% 감소).
- 짧은 가림 포함: 이전 RMSE **0.2399**, 지도/PnP RMSE **0.0807**. 같은 지도에서 1회 복구.
- 순수 회전 180프레임: 이전 10회 잘못된 이동 갱신, 새 버전 0회 초기화.
- 초기화된 지도에서 회전: 한 구간으로 추적 유지. 최대 위치 변화 0.0088 지도 단위. 회전에 대한 완전한 무드리프트 보장은 아님.
- 36프레임 가림: 새 구간으로 분리한 뒤 재초기화·추적 재개. 서로 다른 지도 구간의 전역 연속성·스케일은 보장하지 않음.
- 고정 난수 회귀 테스트: 이동 RMSE 0.0409, 가림 RMSE 0.0587, 정지 구간 drift 0, 정지/순수 회전 오초기화 0. Bootstrap의 난수에 따라 비교 실험과 수치가 달라짐.
- OpenCV vtest.avi 실제 고정 카메라/움직이는 보행자 영상 120프레임: 잘못된 자세 초기화 0, 추적점 중앙값 145. K는 근사값으로 **실제 카메라 이동 정확도 검증이 아님**.
- 데스크톱 합성 테스트 계산 시간 중앙값 약 8.4ms, 95% 약 10.5ms. 디코딩·카메라 노출·GPU readback 제외.
- 브라우저 합성 영상 3,035프레임 관측 시: 같은 구간 유지, 260개 지도점, 재투영 중앙 오차 0.44px, 3,003회 자세 갱신. 콘솔 오류 없음. 모바일 390px 레이아웃 확인.

실제 영상 출처: https://github.com/opencv/opencv/blob/4.x/samples/data/vtest.avi

이 테스트는 제한된 합성 조건과 고정 카메라 영상에 대한 회귀 검사입니다. 실제 폰의 이동 정확도, 발열, 장시간 지도 드리프트, XR 영상/K 정렬은 사용 기기에서 추가 확인해야 합니다.

# 검증 기록

2026-09-29, 개발 Mac의 자동화 Chromium에서 검증. 실제 휴대폰 측정 아님.

- 합성 3D 영상 → OpenCV LK → RANSAC → 상대 자세 → 경로 표시까지 실행. 한 관측 시점에서 172프레임, 7개 자세 갱신, 206개 추적점 확인. 화면 처리율 약 30Hz. 기기 성능 보장은 아님.
- 알려진 회전·이동의 합성 3D 대응점: 이동 방향 내적 1.0, 회전 행렬 오차 약 7.5e-15.
- 잡음 및 25/140 외란 대응점: 이동 방향 내적 0.9991, 회전 행렬 오차 0.0048.
- 잡음 없는 정지 및 순수 회전 입력: 자세 갱신 거부 확인. 모든 실제 퇴화 상황의 안전한 거부를 보장하지 않음.
- 390×844 모바일 viewport: 가로 넘침 없음, 터치 컨트롤 및 레이아웃 스크린샷 확인.
- 합성 DeviceMotionEvent: 가속도와 각속도 값·단위 표시 확인, 연결 해제 뒤 값 변경 없음.
- 카메라 권한 거부 모의 테스트: 안내 문구 및 다시 시작/합성 영상 버튼 복구 확인.
- 페이지 오류 없음, JavaScript 구문 검사 통과.

미검증: 실제 iPhone/Android 카메라·IMU 권한 및 샘플링 주기, 실장면 VO 정확도, 장시간 발열·메모리, HTTPS 배포. GPU 가속 및 VIO 융합 미구현.


## Android WebXR 경로 추가 검증

- 비중앙 주점, skew 포함 projection matrix → K 변환을 GL 좌표 투영과 대조하여 통과.
- 실제 WebGL 렌더링에 합성 카메라 텍스처를 넣어 축소·readback·위아래 방향 확인. 실제 XR 카메라 테스트는 아님.
- K 없이 worker를 실행하여 특징점 208개, pose=null 확인.
- 합성 영상 전체 파이프라인에서 1,174프레임, 36개 상대 자세 갱신 확인.
- 데스크톱 미지원 안내, Android AR 버튼 비활성화, 390px 모바일 레이아웃과 JS 오류 없음 확인.
- **실제 Android 기기에서 XR 세션 권한, 원본 카메라 이미지 정렬, 내부 파라미터 정확도 및 성능은 미검증.** 사용자의 폰에서 확인 필요.
